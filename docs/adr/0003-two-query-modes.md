# Two query modes; light mode is read-only by mechanism

Querying the wiki has two explicit modes with different models and different write capabilities: **light mode** (find existing material fast, cheap/free model, default `opencode/big-pickle`) and **wiki mode** (the Karpathy loop — reason, dialogue, file answers back, frontier model). A single mode was rejected because most lookups don't deserve frontier-model cost, and a cost distinction enforced only by prompt instruction would be cosmetic. Light mode's read-only property is therefore enforced by mechanism — a restricted agent tool profile with write/edit tools disabled — not by asking nicely. Consequences: `AgentBackend.Run` carries the mode as a parameter, every write-capable op (query write-back, ingest synthesis, lint) uses the wiki-mode model class, and both frontends must surface the active mode and model unmistakably.
