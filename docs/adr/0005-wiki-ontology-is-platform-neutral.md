# The wiki ontology is platform-neutral; course pages are conditional on source shape

The wiki's schema and prompts must never name a specific source platform (e.g. boot.dev) or elevate a platform's vocabulary (lesson, chapter) into wiki entities. The ontology knows only: raw source, wiki page (concept page, course page), index, log, schema. A **course page** is created only when a raw source's provenance declares an ordered lesson list — a "course-shaped" source; one-off sources produce concept pages only, and there are deliberately no per-lesson pages. The rejected alternatives: (a) naming boot.dev in the schema, which couples every future wiki to one platform and confuses any agent working on a wiki with no boot.dev content; (b) making course pages universal, which forces artificial course structure onto articles. Platform knowledge lives exclusively in source adapters — acquisition translates any platform into shape metadata (ADR-0001); the wiki only ever sees shapes. Consequences: the schema template, ingest prompts, and UI copy are reviewed for platform names; adding a course platform means adding a `CourseSource` adapter implementation, never a schema change.
